## Claude suggestions: evidence-based disposition

- **Do not automatically adopt the documentation-only oracle exception.** Claude calls it largely unavoidable without email and suggests merely declaring an accepted residual. This is not the owner's acceptance of an A1 exception. Uniform valid-registration response is a bounded mitigation, while composed-flow limits must remain honest. Do not promise perfect privacy or introduce new verification scope.
- **Do not blindly log out on every 403.** Claude's suggested blanket handling is broader than the observed cause. Reconcile `/me`; protect still-valid identity on invalid-CSRF or transient failures. The real probe specifically expired the store row. Absolute expiry is checked on `/me`; it does not by itself erase a row before every other route. Do not generalize all expiry cases into identical CSRF behavior.
- **Timeout implementation is a choice.** Claude's proposed `AbortSignal.timeout` and 8–10 seconds are suggestions. Select an explicit compatible budget and tests; cover JSON parsing, cleanup and safe mutation ambiguity. A generic timeout error is sufficient; do not expose provider/raw errors.
- **Concurrent session touch: independently tested after Claude's source review.** The final Codex probes pause a real `/me` store touch, perform logout, resume the read, then verify the old cookie is still refused. This passed. It does not prove safety for future session-mutating routes or replace any pending-logout/login client sequencing tests needed for the new recovery behavior. No sleep-based race fixes.
- **Forwarded-header bypass: independently tested after Claude's review.** Default production source limits remain enforced across 21 changed identifiers and forged forwarded addresses; the 21st request was 429. No need to weaken proxy validation. A diagnostic library warning occurred only in test stderr.
- **In-repo adapter/older strategy:** documented choices, not automatically P1 vulnerabilities. Current tested touch/update, fixation, replay and expiry boundaries pass. Future private-resource routes must use a reusable expiry-aware authorization guard; `req.isAuthenticated()` alone will not enforce the route-local absolute lifetime.
